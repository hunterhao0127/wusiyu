# 务思语 v1.6.1 三端批注系统设计

## 1. 目标

在不重写现有阅读器的前提下，为 Web、Mac 和 Windows 增加独立的文字高亮与批注能力。三端共用数据模型、定位规则、增删改、冲突合并、备份和导出逻辑。

本版验收后版本号统一升级为 `1.6.1`。发布顺序为 Web 真实使用验证、Desktop 共用接入、Mac 打包验证、Windows 云端构建验证，最后更新 GitHub Pages 和 v1.6.1 Release。

## 2. 范围

### 2.1 本版实现

- 选中阅读原文后提供“翻译、高亮、写批注、加入单词本”。
- 黄、绿、蓝、粉四种高亮颜色。
- 允许纯高亮，也允许在高亮上添加文字批注。
- 再次选中同一批注可查看或继续编辑原笔记；单击高亮仍可查词，双击高亮进入笔记编辑。
- 独立批注面板，默认显示当前书，按原文顺序排列。
- 批注面板支持“全部”和“有笔记”筛选，点击项可跳回原文。
- 当前书的批注可导出为 Markdown。
- JSON 与含书 ZIP 备份自动包含批注，不包含 API Key。
- 删除批注使用墓碑记录，旧备份不会使其复活。

### 2.2 不在本版范围

- 手写、画笔、图片批注、PDF 坐标绘图或多人评论。
- 账号系统、WebDAV 或自动实时云同步。
- Android 发布。
- 全书库全文搜索、标签树或复杂笔记管理。

## 3. 用户交互

### 3.1 建立批注

1. 用户在阅读区选中 1–500 个字符。
2. 现有选择浮层扩展为轻量工具条，保留翻译与单词本能力。
3. 选“高亮”时使用最后一次颜色，首次默认黄色；可立即改色。
4. 选“写批注”时打开编辑器，显示只读原文、四色选择和批注文本框。
5. 保存成功后立即在原文显示高亮，不要求刷新。

空批注文本是合法的，表示纯高亮。完全相同的书籍、内容块与选择范围不重复建立，而是打开已有批注进行编辑。

### 3.2 查看与管理

- 工具栏增加“批注”入口和当前书批注数量。
- 列表项显示原文摘录、批注正文、章节、颜色和时间。
- 列表按内容块与起始位置排序，不使用会随字号改变的页码。
- 点击列表项时切换到相应页或滚动位置，并短暂强调目标高亮。
- 删除前要求确认；删除后同步刷新原文和列表。

### 3.3 Markdown 导出

导出顺序与原文一致，包含书名、章节、原文引用、批注正文和创建时间。纯高亮也保留原文引用。文件名为 `书名-批注-YYYY-MM-DD.md`。

## 4. 数据模型

`SyncRecord.type` 增加 `annotation`。每条记录使用 `annotation:<uuid>` 作为稳定 ID：

```typescript
type Annotation = {
  id: string
  bookId: string
  bookAliases: string[]
  blockIndex: number
  startOffset: number
  endOffset: number
  quote: string
  prefix: string
  suffix: string
  chapterTitle: string
  color: "yellow" | "green" | "blue" | "pink"
  note: string
  createdAt: number
  updatedAt: number
}
```

约束：

- `bookId` 优先使用原文件 SHA-256，旧书可携带规范化文件名别名。
- `startOffset` 和 `endOffset` 是内容块纯文本内的偏移，不依赖 DOM 节点结构。
- `quote` 必须与选中文本一致，首尾空白被移除后重新计算偏移。
- `prefix` 与 `suffix` 各保留最多 32 个字符，用于位置回退。
- `note` 最长 10000 个字符。
- 修改颜色或批注只更新原记录，不改变 ID 和创建时间。
- 删除生成 `payload: null` 的同 ID 墓碑。

## 5. 定位与渲染

### 5.1 建立锚点

只允许从同一个可批注内容块中建立批注。用户跨段选择时提示“请在同一段内批注”，不尝试拆成多条隐式记录。

DOM Range 首先转换为内容块纯文本偏移，然后交给共享核心校验和创建记录。数据模型不保存 CSS 选择器、HTML 或页码。

同一内容块内不允许两条批注部分重叠；点击已有高亮直接编辑原批注，避免嵌套标记导致错位。批注高亮与单词本下划线仍可重叠显示。

### 5.2 恢复顺序

1. `bookId + blockIndex + startOffset/endOffset` 与 `quote` 直接匹配。
2. 偏移不匹配时，在原内容块中使用 `quote + prefix/suffix` 重新定位。
3. 原内容块无法恢复时，只在相邻少量内容块中查找唯一匹配。
4. 找不到或出现多个无法消除歧义的匹配时，返回“原文位置已变化”，保留批注内容，不猜测跳转。

### 5.3 与单词本标记共存

批注使用半透明背景色，单词本继续使用下划线。两者可重叠，不互相删除或替换。渲染使用纯文本偏移，不把用户批注或原文当作 HTML 执行。

## 6. 共享模块与平台接入

```text
shared/
├── core/reader/annotation.js
└── ui/annotation-panel.js
```

- `annotation.js` 负责模型校验、新建、更新、删除、排序、锚点恢复和 Markdown 生成，不访问 DOM 或存储。
- `annotation-panel.js` 负责共享的工具条、编辑器与列表界面，通过回调读写记录和跳转位置。
- Web 继续使用 `WebStorageAdapter`，Mac/Windows 继续使用 `DesktopStorageAdapter`。
- `scripts/prepare-shared-assets.mjs` 将两个新共享文件发布到 Web 和 Desktop 静态目录，`--check` 防止副本漂移。
- Web 和 Desktop 入口只保留阅读器状态与 DOM 的薄连接。Mac 和 Windows 共用 Desktop 页面与 Flask 后端，不创建 Windows 专用批注实现。

## 7. 备份、合并与兼容

- 现有 `wusiyu-learning-backup` v2 容器格式不变，记录类型扩展为 `annotation`。
- v1.6.1 可以导入现有 v1/v2 备份。
- 含 `annotation` 的备份需使用 v1.6.1 或更高版本导入；v1.6.0 会安全拒绝不认识的记录类型，不执行部分导入。
- 同 ID 记录继续使用 `updatedAt` 较新者获胜；时间相同时墓碑优先，再以 `deviceId` 确定性决胜。
- API Key、认证头、翻译缓存和临时状态不进入备份。

## 8. 错误处理

- 跨内容块选择、空选择、超过 500 字符或无法得到稳定书籍标识时不写入记录，显示可理解的中文提示。
- 存储失败时不在页面上留下未持久化的假高亮。
- 批注锚点无法恢复时保留笔记和原文摘录，仅禁用跳转，不自动删除。
- Markdown 导出失败不影响本地批注。
- 同步备份导入先完整校验再写入，错误时不改动当前记录。

## 9. 验收标准

### 9.1 共享核心

- 新建、更新、删除、去重、排序和墓碑合并的自动测试通过。
- 直接偏移、原块重定位、相邻块唯一匹配和歧义失败的测试通过。
- Markdown 导出正确转义标题、引用和批注内容。
- v1/v2 旧备份继续可导入，新批注可导出、恢复、合并和删除。

### 9.2 Web 真实页面

- 完整走通选中文字、四色高亮、写批注、立即显示、刷新恢复、修改、换色、删除和列表跳转。
- 切换分页/滚动、字号、边距、段距和双栏后批注仍定位在同一原文。
- 单词本下划线与批注背景可同时显示，现有翻译、复习、目录、阅读位置和备份不退化。
- Markdown、JSON 和含书 ZIP 都使用真实数据导出并重新导入验证。
- 页面无新增未处理控制台错误。

### 9.3 Desktop 与发布

- Desktop 源码页完成与 Web 同样的主要批注流程，关闭重开后保留。
- Mac 重建 PyInstaller 后端和 Electron DMG，安装后真实运行并返回 1.6.1。
- Windows GitHub Actions 通过共享测试、后端构建、真实启动冒烟和 NSIS 安装包构建。
- GitHub Pages 线上文件与验证后 Web 源码一致，v1.6.1 Release 包含新 Mac DMG 和 Windows EXE 及 SHA256。
- Windows Defender、SmartScreen、快捷方式和真机覆盖升级依然标记为“未真机验证”，不由云端构建代替。

## 10. 实施顺序

1. 用测试固定批注模型、锚点、墓碑与 Markdown 规则。
2. 实现共享核心和共享 UI，通过 Web 薄接入与 IndexedDB 保存。
3. 完成 Web 自动检查和真实页面验收；未达标前不接入 Desktop。
4. 接入 Desktop 页面，复用同一核心与 UI，验证 Flask 存储与备份。
5. 统一升级版本号、更新说明和下载地址。
6. 重建并验证 Mac，上传源码后由 GitHub Actions 构建并验证 Windows。
7. 发布 Web 与 v1.6.1 Release，再回读线上文件和附件摘要作最终核对。
